# Architecture and Contracts

## System overview

```text
SwiftUI application
  |-- composer + mode policy
  |-- living brief renderer
  |-- evidence map + passage inspector
  |-- run history, settings, export, learning view
  |
  |
  | versioned commands/events over authenticated local IPC
  v
ResearchCore sidecar, extracted from the proven sibling engine
  |-- trusted state machine and budgets
  |-- query and acquisition coordination
  |-- search/fetch/extraction/retrieval adapters
  |-- evidence ledger and citation validator
  |-- SQLite/FTS5 and content-addressed artifacts
  |
  +--> native LanguageModel adapter boundary where appropriate
```

The initial hybrid architecture is deliberate. Reimplementing the mature
Python research pipeline in Swift would delay a useful product and discard 184
existing tests. The native app owns product experience and validates every
sidecar message. The sidecar owns proven research mechanics. Components may be
ported later only with measured packaging, performance, or maintenance evidence.

The shipping app bundles and supervises the sidecar. A normal user does not
install Python or run Docker. The contributor path may use the pinned Python
environment until release packaging is proven.

## Research state machine

```text
created -> scoped -> rewriting -> searching -> acquiring -> extracting
        -> retrieving -> building_evidence -> drafting -> validating -> complete
```

Deep mode may make the bounded transition:

```text
building_evidence -> checking_gaps -> follow_up_search -> searching
```

Any active state may terminate as:

- `cancelled`;
- `budget_exhausted`;
- `failed`; or
- `needs_user_input`.

Only the controller changes state. Adapters emit typed results and failures.

## Core domain entities

| Entity | Purpose | Critical fields |
|---|---|---|
| `ResearchRun` | Immutable run identity and configuration | question, mode, config digest, status, budgets, timestamps, stop reason |
| `ModePolicy` | Frozen bounds and provider rules | query/source/round limits, time scope, source constraints |
| `QueryRewrite` | Auditable search intent | original question, query, purpose, parent query, provenance |
| `SearchHit` | Discovery metadata, never evidence | provider, query, rank, URL, title, snippet, observed time |
| `Source` | Canonical publication identity | canonical URL, domain, author/publisher, dates, source type |
| `Snapshot` | Bytes and text actually observed | source ID, fetch time, response metadata, hashes, extractor version |
| `Passage` | Addressable evidence unit | snapshot ID, ordinal, heading path, offsets, text hash |
| `Claim` | Atomic externally checkable proposition | qualifiers, time, scope, confidence, status |
| `EvidenceLink` | Relationship between claim and passage | relation, quote, provenance, reviewer status |
| `AnswerBlock` | Trusted adaptive presentation unit | type, content, claim IDs, layout-safe fields |
| `Citation` | Compiled claim-to-evidence marker | answer offsets, claim ID, evidence IDs |
| `Evaluation` | Reproducible quality record | metric versions, scores, failures, evaluator identity |

IDs and hashes are generated by trusted code. Model output may reference only
IDs present in its supplied context. Unknown fields fail validation.

## Citation compilation

```text
verified claims
  -> answer outline
  -> structured answer blocks naming claim IDs
  -> deterministic citation placement
  -> integrity validation
  -> rendered answer
```

The writer does not receive arbitrary URLs and cannot invent citation markers.
If a factual span has no accepted claim/evidence link, validation either removes
the span, labels it as uncertainty, or rejects the draft.

## Search boundary

```swift
protocol SearchAdapter {
    func search(_ query: String) async throws -> SearchOutcome   // .hits([SearchHit]) | .noResults(query:)
}

protocol SearchTransport {                                        // the only socket boundary
    func send(_ request: SearchRequest) async throws -> SearchResponse
}
```

An adapter never owns a connection: every request travels through an injected
`SearchTransport`, so provider logic is testable without network access and the
production `URLSession` implementation stays a thin, single-purpose edge.

Typed outcomes are mandatory. `SearchError` covers `invalidEndpoint`,
`emptyQuery`, `transportFailure`, `httpStatus`, and `malformedPayload`; an empty
but successful provider response is the typed empty outcome `.noResults`, not
an error and never a silent success. Cancellation is not folded into
`transportFailure`: it stays `CancellationError` so the run-level state machine
owns the terminal `cancelled` transition.

Hit identity is content-derived (`query`, fragment-free URL, provider rank), so
the same search observation is reproducible across runs. Provider payloads are
not our frozen wire schema, so unread provider fields are ignored, while every
field the adapter consumes is validated strictly and any uninterpretable
payload fails closed.

Initial adapters:

- deterministic fixture provider for M001 (implemented);
- SearXNG JSON for the live baseline in M002 (implemented, M002.1);
- academic metadata providers in M004; and
- optional Exa comparison only after the baseline is measured.

Raw provider responses are private diagnostics. Normalized hits are persisted
with the run. Search snippets never become passages.

## Acquisition boundary

Before a live request, trusted code must:

1. allow only HTTP and HTTPS;
2. reject private, loopback, link-local, multicast, and metadata-service
   destinations, including redirects and DNS rebinding cases;
3. apply robots and explicit domain policy;
4. apply per-host concurrency and delay;
5. enforce redirect, timeout, byte, character, and MIME limits; and
6. avoid login, form submission, CAPTCHA solving, and paywall bypass.

Static HTTP is the default. Browser rendering is a separately recorded fallback.
PDF extraction has its own adapter and page-aware passage identifiers.

## Snapshot and passage boundary

Snapshots are content-addressed and immutable within a completed run. A
passage retains normalized offsets, heading context, and its own hash. Later
changes to a live page cannot silently modify old evidence.

Private downloaded bodies do not enter Git. Redistributable deterministic
fixtures are small, attributed, and frozen in the repository.

## Retrieval boundary

The first baseline is:

1. URL canonicalization;
2. exact-content deduplication;
3. basic near-duplicate detection;
4. source-type, recency, directness, and independence features;
5. FTS5/BM25 passage retrieval; and
6. diversity selection.

A reranker is an adapter added only through `docs/MODEL_POLICY.md`. The
controller must remain functional when no reranker is configured.

## Adaptive answer blocks

The selected UI needs richer output than unrestricted Markdown, but generative
UI must remain safe and testable. The model selects from a finite schema such
as:

- `prose`;
- `comparison_table`;
- `timeline`;
- `paper_matrix`;
- `recommendation`;
- `uncertainty`;
- `conflict`; and
- `next_questions`.

SwiftUI owns rendering. Model output cannot provide Swift, HTML, JavaScript,
colors, arbitrary layout, or executable actions.

Every factual field in an answer block must name a known claim ID. Every
accepted claim must resolve to one or more saved passages. The schema is
inspired by A2UI's separation of component structure and data, while the stream
uses AG-UI-like lifecycle and snapshot/delta patterns. Neither external protocol
is a required runtime dependency in v1.

## Inference boundary

`LanguageModel` exposes structured generation and token streaming without
leaking provider types into the controller.

Planned order:

1. deterministic fake in M001;
2. Apple's common `LanguageModel` protocol as the native abstraction on
   supported systems, with mode-specific Dynamic Profiles;
3. one supported local candidate in M003, selected under the model policy and
   exposed through that boundary where practical; and
4. optional hosted reference adapter kept separately labelled.

Local and hosted outputs, timings, costs, and benchmark scores are never merged.

## Persistence

SQLite stores normalized entities, FTS5 indexes passages, and the application
support directory stores content-addressed private artifacts.

Each run also exports an append-only event stream and a versioned provenance
bundle so evaluation does not depend on current application state.

## Native integration boundary

The application may add these only after the core run works:

- global Quick launcher;
- Core Spotlight indexing of saved research;
- App Intents and Shortcuts;
- Share extension for selected text or URLs;
- Quick Look for exported research; and
- Keychain-backed provider settings.

## Dependency rule

Every dependency requires:

- the product capability it enables;
- why the standard library or existing dependency is insufficient;
- licence and distribution impact;
- package size and runtime cost; and
- a removal or replacement boundary.

Do not introduce an agent framework, vector database, or new background
service merely because a reference project uses one. The Python runtime is the
single approved exception because it preserves an existing tested research
core; its bundle cost and reliability are explicit M001/M003 gates.
